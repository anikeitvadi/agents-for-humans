What changed, by area:
- **Identity** (`agent/packs/immigration/pipeline.py`): a submission's ledger key (`event_id`) is now derived from the complete extraction result — fields, evidence, statuses, mode, and a sha256 of every uploaded document — not a fixed placeholder or the dates alone. Two different document sets that happen to extract the same dates get distinct identities and never inherit each other's draft or approval; the full result is persisted under that key (`get_persisted_result`) so replay/guardian/approval all refer to the exact artifact reviewed.
- **Upload validation** (F2/F3): every file is actually decoded (Pillow `verify()`, not just magic bytes) before any model call — a truncated file with a valid PNG signature is rejected. In recorded mode, uploaded bytes must hash-match a known bundled specimen before the reply is trusted; a client that fails over from live to recorded *mid-batch* is refused as a whole rather than silently mixing a live field with recorded ones.
- **Concurrency/reset** (F4, review pt 6): `/api/process-documents` offloads the synchronous pipeline to a threadpool so a slow extraction never blocks the event loop; `Store` gained a reset epoch — a request that captured its epoch before a slow call started aborts (`ResetEpochMismatch`) if `/api/reset` ran while it was in flight, instead of writing a result afterward. The `record_action`/`get_action` deadlock risk from combining main's receipts with the local per-statement lock was fixed with an unlocked internal read helper.
- **Guardian bound to the uploaded case** (`agent/llm/guardian.py`): a new `check_uploaded_case` tool, closed over a per-request `current_submission_ref` (sent by the UI from the last `/api/process-documents` response), reports on that specific persisted result — never a silent rerun of the bundled sample. `run_sample_case_check` stays as the separately-named bundled-demo tool.
- **UI** (`ui/index.html`): rebuilt from the upload-flow single-story layout (no recall tab), with main's Ask-the-guardian, approve-for-attorney-review, and reset features grafted in; a one-click "Load bundled sample & process" shortcut; `apiFetch` extended for multipart FormData and a checked binary download path; upload controls disabled during processing plus a submission-version guard so a stale in-flight response can never overwrite a newer one.
- **Recall pack**: backend/pipeline/tests fully intact, no longer surfaced in the UI (per direction).
- **Two real bugs found only by live Bedrock verification** (`agent/llm/extract.py`): the model wraps its JSON response in a markdown code fence even when told not to (now stripped before `json.loads`); without an explicit instruction the model returns dates in the document's own printed format (`11/03/2026`), which R3's ISO validation would otherwise always flag as `ambiguous` — the prompt now asks for ISO-normalized `value` while keeping the original printed text as `evidence`. Confirmed working end to end: live upload → correct ISO fields → surfaced discrepancy → LLM-personalized draft (`used_llm_personalization: true`) → guardian's `check_uploaded_case` reporting on that exact case, live, with a correct decision trace.
