# Bulletin fixtures

`2025-09.json` and `2025-10.json` are two real, consecutive DOS Visa Bulletin months paired with the matching-month USCIS "which chart applies for filing" designation, used by the unattended bulletin poll (`agent/packs/immigration/bulletin.py`) and its tests (`tests/test_bulletin_poll.py`).

They were chosen because they capture a real, well-documented event: USCIS switched the designated chart for employment-based filing from **Final Action Dates** (September 2025) to **Dates for Filing** (October 2025) — the first bulletin of FY2026 — which is exactly the "DOS publishes both charts, USCIS separately designates which one applies" scenario `check_bulletin_cutoff` exists to handle. `seeded_case.json` is a synthetic EB2-India case (invented priority date/person) whose priority date is not current against September's Final Action cutoff and current against October's Dates for Filing cutoff — the poll's demo beat.

**Provenance:** each file's `source_provenance` records the primary government URL (travel.state.gov / uscis.gov) and the date verified. The primary travel.state.gov pages returned HTTP 403 to automated fetching during this session, so the cutoff values were corroborated against independent legal-industry coverage of the same bulletins instead (`verification_sources`) — replace with a direct capture of the primary page if/when it becomes fetchable, per this project's rule that rule inputs must be real captured data, not invented.

Retrogression (a chart moving backward between two consecutive months of the *same* chart type) is intentionally **not** exercised by this fixture pair, since September used Final Action and October used Dates for Filing — comparing across different chart types would be a category error, not a real backward move (`agent/packs/immigration/bulletin.py::run_bulletin_poll` skips the retrogression comparison whenever the two months' chart types differ). Retrogression handling itself is proven separately against hand-verified constructed fixtures in `tests/test_immigration_rules.py` — see `docs/architecture-spec.md` §7a.
